作成日: 2026-09-20  
状態: 2026-09-20 ユーザー承認済み・実装とUnity検証完了  
ブランチ: `codex/realistic-spiderweb`

## 目指す見た目

**トンネルに残った、薄く、少し傷んだ蜘蛛の巣。**

壁に張られた支え糸の間に、細い横糸が不均一に渡る。中心は少し偏り、下側の糸はわずかにたわむ。懐中電灯を動かすと、その方向に合う糸だけが銀白色に浮かび、照らされない部分は背景へ溶け込む。破れは局所的に集まり、残った糸から元の構造が読み取れる。

既存のアンカー配置を生かし、糸の密度・張力の差・照明への反応を改善する。

## 提案する変更

### 1. 糸の質感と照明

- 糸の横断面に滑らかな被覆率を作り、両端が背景になじむようにする。スクリーン微分を用いて細線のちらつきを抑える。
- 糸方向の接線をメッシュへ保持し、接線に沿う繊維の反射を計算する。カメラ正対の平面法線だけで反射を決めない。
- URPのMain LightとAdditional Lightsに対応し、距離・影・ライト色を反映する。Forward/Forward+をプロジェクトのURP版に合わせて確認する。
- 常時明るいハイライトを抑え、暗所の基礎色と光が当たった部分の差を作る。
- 最初の候補はプリマルチプライド透明描画。糸が重なる箇所の濃さ、霧、深度、遠景のちらつきを比較して採否を決める。
- `_BaseColor` とそのアルファ値を維持し、既存の燃焼フェードを引き続き使う。

### 2. 張った糸とたわんだ糸

- 放射糸は比較的まっすぐ、横糸は3〜4区間の曲線として描画する。
- 曲線の両端は元の物理ノードに厳密に一致させる。描画のためだけに物理ノードを増やさない。
- 横糸の初期たわみは区間長の1〜3%を調整開始点とし、長い糸ほど自然に垂れるようにする。壁に沿わせる設定では貫通しないよう抑える。
- 横糸の幅は放射糸の45〜65%を開始点とする。一本の途中の太さ変化は連続させ、接点が不自然に膨らむのを抑える。
- 現在のシーンの `threadWidth=0.0005` を考慮し、単に細くするだけで消えてしまわないよう遠距離の視認性も調整する。

### 3. 手動アンカーから独立した描画密度

- 実際の固定点8個は維持し、見える放射糸は設定値32本を目標にできるようにする。
- 最初は既存の物理ノードを補間して描画用の糸を増やす。追加糸の端点は外周の支え糸上に置き、空中の固定点を作らない。
- 描画用の糸は既存物理の変形へ追従する。追加糸ごとの独立した張力シミュレーションは今回の対象に含めない。
- 手動アンカー由来のコライダー生成には元のアンカー一覧を使い、接触範囲を維持する。
- 支え糸と追加糸の接続が破れで途切れないよう、欠損を作る前に支持関係を確定する。

### 4. 不均一さと経年表現

- 均一な同心多角形を弱めるため、描画上の横糸の間隔と位相を少しずつずらす。接点は放射糸上に置く。
- 補強の斜め糸は少数に抑え、破れの近くなど構造上の意味がある場所へ寄せる。
- 破れを局所的な領域へまとめる。断端の垂れや糸の濃淡は控えめに加える。
- 同じseedでは同じ見た目になるよう、描画用乱数を既存の物理生成用乱数から分離する。

## 実装とレイヤー方針

- コードは正式な `Assets/Shinzui/` 配下で管理する。2026-09-20の `agents.md` 更新に合わせ、`app_build/SpiderWeb/` は比較画像・検証記録だけに使用し、ソースの複製や同期スクリプトを残さない。既存ファイルの `.meta` とGUIDは維持する。
- 初回の変更は描画用メッシュ、シェーダー、表示設定、Editor設定UIに限定する。描画のための補間・曲線サンプリングはViewの描画責務として扱う。
- ViewからPresentation、Application、Domain、Infrastructureへの依存を追加しない。PresentationからDomain/Infrastructureへの依存も追加しない。asmdefの依存方向を維持する。
- 既存の物理・プレイヤー拘束・燃焼の制御を別レイヤーへ移す大規模な再設計は本案の対象外。見た目改善にゲームルールを追加しない。
- 既存の公開API、手動アンカー参照、Inspectorの既存フィールドを維持する。既存シーンには新しい表示パラメーターを適用し、C#の初期値変更だけで反映済みとしない。
- メッシュ用配列を生成時に確保し、毎フレームの割り当てを避ける。Boundsには手動アンカー、曲線のたわみ、変形範囲を含める。

## 確認方法と完了条件

1. `LatestStageGenerateTemp` の同じアンカー・カメラ・照明条件で変更前後を撮影する。正面、斜め、近距離、遠距離を比較する。
2. 懐中電灯を左右から当て、光の位置に応じてハイライトが移ることを確認する。ライトなし・逆光・霧ありも確認する。
3. 8アンカー・放射糸32本の設定で表示密度が増え、固定点とコライダー数8個を維持することを確認する。
4. 同じseedで同じ描画形状、曲線端点と元ノードの一致、有限の頂点座標、十分なBoundsを検証する。
5. 接触変形、拘束・解放、再生成、無効化・再有効化、燃焼フェードが従来どおり動くことを確認する。
6. Unityのコンパイル、シェーダーのエラー確認、既存SpiderWebテストを実行する。各画質設定で透明描画、細線、影、霧の崩れを確認する。
7. 描画負荷と更新時の割り当てを変更前と比較し、増えた頂点数とCPU/GPU時間を記録する。新たな毎フレームGC allocationを発生させない。
